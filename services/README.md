# LazyScale — service definitions

What we sell, what's included, where the boundaries are, and how each build is
delivered. This is the internal document. The website is the marketing version of it.

Two rules underneath everything here:

1. **Nothing irreversible happens without a human approving it**, unless the client
   explicitly asks for autonomy and understands what they are accepting.
2. **We only promise what the workflow actually does today.** Not what it will do
   after one more evening of work.

---

## The two headline services

### 1. Speed-to-Lead — from ₹4,999/month

Every enquiry answered in under 60 seconds, whatever time it lands.

**Included**
- One intake webhook, connected to up to 3 sources (website form, WhatsApp, Instagram, IndiaMART, email parsing)
- Lead scored 0–10 against criteria we agree with the client
- Personalised first reply drafted and sent
- Team alert in Slack, WhatsApp or email, with the score and a summary
- Every lead logged to Sheets, Airtable or their CRM
- 30 days of monitoring after launch

**Not included** (these are quotable extras)
- More than 3 lead sources
- Multi-step nurture sequences
- Anything that writes back into a CRM with custom field mapping
- Phone calls or voice

**Delivery: 48 hours** from receiving credentials.

**What makes it work:** the scoring criteria. Spend the kickoff call getting the
client to describe their best three customers and their worst three enquiries in
concrete terms. Vague criteria produce a scorer that rates everything a 7.

### 2. WhatsApp Autopilot — from ₹7,999/month

Routine WhatsApp questions answered instantly. Real ones escalated to a human.

**Included**
- Connection to their WhatsApp Business API through their BSP
- A knowledge base we build with them, covering hours, pricing, location, policies, FAQs
- Automatic replies to anything the knowledge base covers
- Escalation to a human for anything it does not
- Out-of-hours handling with an honest "someone will follow up" message
- Conversation log, and a monthly review of what got escalated

**Not included**
- WhatsApp Business API provisioning and Meta verification (client's own account, we assist)
- Template message approval (we draft, Meta approves, timing is theirs)
- Payments or order processing inside chat
- Broadcast or bulk campaigns — see the boundaries section

**Delivery: 3–5 working days**, plus however long Meta takes to verify.

**What makes it work:** the knowledge base is the entire product. Anything not in it
gets escalated, which is correct but means a thin knowledge base equals a useless bot.
Budget real time for building it, and review escalations monthly — a repeated
escalation intent is a gap to close.

## What we do not build

These are refusals, not negotiations. Every one of them has ended someone's agency.

- **Fully autonomous cold outbound.** Deliverability damage, legal exposure under
  anti-spam rules, and it makes us the spam vendor. We will build reply handling for
  outbound the client sends themselves.
- **WhatsApp bulk broadcast to scraped or purchased lists.** Gets the client's number
  banned and is a policy violation. Opt-in lists through approved templates only.
- **Executing payments, transfers or trades.** One bug ends the business.
- **Anything irreversible with no human approval**, unless explicitly agreed in writing.
- **Scraping behind a login**, or anything that needs a CAPTCHA solved.
- **Medical, legal or financial advice generated by a model** and sent to end users.

If a prospect insists, decline the project. The revenue is never worth it.

## Qualifying a project before quoting

Score any request against these four. **Two failures means walk away or rescope.**

1. **Does the pain recur weekly or more?** Annual pain is not worth automating.
2. **Is the saving countable** in hours or rupees? If nobody can name a number, nobody
   will renew.
3. **Can a human approve** before anything irreversible? If not, the risk is ours.
4. **Do they already own the tools?** If it needs a migration first, that is a
   different, larger project.

Additionally, check the API actually exists and is stable. "It has an API" and "it has
an API we can use on their plan" are different sentences. Verify before quoting — the
Tally, Zoho and IndiaMART integrations in particular have caught people out.

## Standard delivery sequence

1. **Discovery call, 30 minutes.** Map the process as it happens today. Get concrete
   examples, not descriptions. Ask for three real recent cases.
2. **Written proposal.** Four-step workflow description, price, timeline, and what is
   explicitly out of scope. Nothing starts until this is agreed.
3. **Access.** Credentials into a password manager, never over WhatsApp or email.
   The clock starts here, not at signature.
4. **Build.** Import the template, adapt the Config node, wire their tools.
5. **Test with their real data.** At least ten real historical cases through the
   workflow before anything sends to a real person.
6. **Shadow run, 2–3 days.** Everything drafts, nothing sends. Client reviews output.
7. **Go live**, with the human-approval steps they chose.
8. **Monitor 30 days.** Defects in what we built are fixed free. Changes to what it
   should do are new work.
9. **Monthly review.** What got escalated, what got mis-scored, what to tune.

Steps 5 and 6 are the ones people skip when they are in a hurry. They are also the
only reason the launch goes quietly.

## Per-client operational checklist

- [ ] Credentials stored in a password manager, not in a chat
- [ ] Client owns every third-party account; we hold access, not ownership
- [ ] Hard monthly spend cap set on the LLM API key
- [ ] Rate limit on every public webhook
- [ ] Free-text wrapped as untrusted data before it reaches a prompt
- [ ] Error path routes somewhere a human sees, not into silence
- [ ] Client knows exactly which steps are autonomous and which need approval
- [ ] Handover doc written before the retainer starts, not when it ends

## The workflows

Importable n8n templates live in [`workflows/`](workflows/). Each one has a **Config**
node at the front holding every client-specific value — the prompt, the channel, the
thresholds. **That node should be the only thing you edit per client.** If you find
yourself changing logic in a Code node for a specific client, that is a signal the
template needs a new config option instead.

Import: n8n → Workflows → Import from File. Then add credentials, edit Config, and run
it manually with test data before enabling the trigger.

See [`workflows/README.md`](workflows/README.md) for per-workflow setup.
